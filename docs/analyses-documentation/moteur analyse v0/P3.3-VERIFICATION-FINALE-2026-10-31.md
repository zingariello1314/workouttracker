**Date :** 2026-10-31

## 1. Verdict

**P3.3 partiellement validé avec restriction de fiabilité.**

| Critère | Verdict |
| --- | --- |
| Capture sans activité (contenu candidat) | **Oui** |
| Repos prévu ≠ séance manquée | **Oui** |
| Immutabilité `historical_frozen` | **Oui** |
| Promote provisional → **pas** `high` automatique | **Oui** (corrigé) |
| `sealPlanBeforeProgramChange` branché sur mutations actives | **Oui** (corrigé) |
| Jours incertains exclus P3.0 / P3.1 / P3.2b | **Oui** (corrigé) |
| Preuve `high` pour toute journée scellée tardivement sans démonstration | **Non** — interdit |

La capture sans activité est opérationnelle. La **preuve comparative fiable** (`planCompareEligible` / `compareReliability: high`) exige une applicabilité **démontrée** (`proven`), pas la seule proximité calendaire ni le passage de minuit.

## 2. Défauts démontrés et corrigés

### D1 — Promote aveugle en `high`

**Avant :** `promoteDueProvisionalForecasts` passait toute prévision passée en `historical_frozen` ; `describeDayPlanProvenance` et la matrice traitaient tout frozen comme snapshot high.

**Après :** promote → `historical_frozen` + `applicabilityConfidence: unverified` (sauf si déjà `proven`). Matrice : source `live`, hors dénominateur.

### D2 — Seal API non branchée

**Avant :** `sealPlanBeforeProgramChange` uniquement testé.

**Après :** appelé depuis `useWorkoutPrograms` avant `activateProgram` / `deactivateProgram` / `updateProgram` (programme actif) / `deleteProgram` (si actif), via `WorkoutContext.sealPlanBeforeMutation`. Les prévisions futures sont invalidées (`clearFutureProvisionalForecasts`).

### D3 — Proximité = fausse preuve

**Avant :** reconcile / CalendarHeatmap forçaient `programApplicabilityProven` pour hier / J-2.

**Après :** sans preuve → hier = `unverified` ; plus ancien = `indeterminate`. Jamais `proven` par absence de journal de mutations.

### D4 — Provisional / indeterminate / unverified dans les analyses

**Avant :** tout snapshot non-reconstruct → `PLAN_SOURCE.SNAPSHOT`.

**Après :** `resolveDayPlanReadOnly` :
- provisional → `live`
- indeterminate → `none`
- historical unverified → `live` (contenu visible, hors adhérence)
- historical proven (ou legacy perf) → `snapshot`

## 3. Contrat de fiabilité (A1)

| Statut / confiance | Provenance typique | `compareReliability` | Dénominateur P3.0/3.1/3.2b |
| --- | --- | --- | --- |
| `provisional_forecast` | forecast proactive | `provisional` | Non |
| `historical_frozen` + `unverified` | promote minuit, backfill app open | `unverified` | Non |
| `historical_frozen` + `proven` | perf, calendar_save, seal avant mutation, explicit proven | `high` | Oui |
| `indeterminate` / `unknown_historical` | passé sans preuve | `none` | Non |
| Legacy P3.0 sans `status` | perf historique | `high` (assumé proven) | Oui |

**Promotion en preuve historique fiable :** seul un trigger démontrable (perf / save / seal avant mutation / capture explicite prouvée) pose `applicabilityConfidence: proven`. Une prévision devenue passée **ne devient pas** `high` seule.
