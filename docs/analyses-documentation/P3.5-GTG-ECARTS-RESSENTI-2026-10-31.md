## Clôture — vérifications ciblées (31 oct. soir)

### 1. Déduplication GTG / workoutSync

**Bug trouvé :** `classicExclusiveRepsForDay` faisait `Σreps(jour) − Σsync(jour)`, ce qui pouvait diminuer artificiellement d’autres exercices quand `sync > classic` sur une clé.

**Correction minimale :** soustraction **par clé de stockage** (`resolveGtgCanonicalExerciseId` / même résolution que `syncGtgDayToWorkoutData`).

| Cas | Comportement |
|-----|----------------|
| Sync normale | Retire uniquement le ledger sur la clé correspondante |
| GTG non synchronisé / ledger absent | Aucune soustraction |
| Resync / suppression de passage | Suit le ledger **courant** (pas un cumul) |
| Plusieurs exos / jour | Isolé par clé |
| Sync > classic sur une clé | Clamp à ce volume ; **autres clés intactes** ; `reliable: false` |
| Identité ambiguë | Déduction par clé storage OK ; **pas** de carte part mouvement |
| Isométriques | Hors map `reps` — non convertis, non soustraits |
| Provenance sync clampée | Abstention métrique combinée (`sync_provenance_unreliable`) |

### 2. Dénominateurs

Couverture explicite : `classicActiveDays`, `classicOnlyDays`, `gtgActiveDays`, `gtgOnlyDays`, `bothDays`, `daysWithoutClassicExclusive`, `daysWithNoRecordedActivity` + invariants `consistency.partition / withoutClassic / activeEqualsParts`.

Formulations : « exclusivement classiques / GTG » (canal jour) ≠ « classicExclusiveReps » (volume hors sync).

### 3. Rivalité éditoriale

- **Retiré** : rivalité `gtg_outside_classic` ↔ `disc_gtg_unplanned_*` (phénomènes distincts : calendrier sans séance vs hors horaires).
- **Conservé** : `gtg_coexistence` ↔ `gtg_outside_classic` (deux angles sur la répartition des canaux — une seule place pack).

Rejeu : outside n’est plus éliminé par unplanned ; écarté seulement en rival de coexistence quand les deux sont produits.
