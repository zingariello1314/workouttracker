## 6. Portes E–H — Correctifs livrés

### Architecture (Porte I, justifiée)

Couche commune **sans nouvelle source de vérité** :

| Fichier | Rôle |
|---|---|
| `workoutAnalyticsRevision.js` | Empreinte légère reps/coches/coeffs/endurance |
| `groupedCheckedRepsCache.js` | Une agrégation checked-reps par révision |
| `sportRecapAggregatesCache.js` | Cache borné muscle + muscu (mêmes fonctions métier) |

Les moteurs `computeRecapMuscleState` / `buildRecapStrengthCompareModel` restent la vérité analytique ; le cache ne change aucun coefficient.

### Modules branchés

- **Body** (`SidebarBodyRecapModule`) : différé + `getCachedRecapMuscleState` ; indicateur « maj… ».
- **Muscu** (`RecapStrengthStatsCard` variant sidebar) : différé + `getCachedRecapStrengthCompareModel`.
- **Calendrier** (`SidebarSportCalendarModule` + `CalendarHeatmap` embed) : historique différé ; snapshot analytique différé dans le heatmap sidebar ; invalidation intensité par révision ; `getIntensityForDate` lit le snapshot différé en embed.

### Effets attendus

- Paires StrictMode (~650+620 ms) → 2ᵉ hit cache.
- Après Enregistrer : commits sidebar **déférés** ; coches restent urgentes.
- Pas d’augmentation des timeouts 80/140/200 ms.

### Calendrier — limite restante

`sidebar.calendar.history` ≪ coût Profiler : le rendu + `getIntensityForDate` (≈30 jours) restent intrinsèques. Le différé évite de les exécuter sur le chemin urgent ; une extraction Worker des intensités reste une piste si le P95 post-save reste > 100 ms.
