## 3. P0.5-A / B — Bande ~470 ms = panneau Flight Recorder

### Preuve

Fenêtre ~56,8 s → 116,4 s : occupation LT ~95,8 %, SidebarPremium ~17 ms, TodayTab ~322 ms, pas d’XP.

| Observation | Valeur |
|---|---|
| LT dans la bande | 155 |
| Durée médiane LT | 460 ms |
| Écart médian entre démarrages LT | **467,4 ms** |
| Code panneau (avant correctif) | `setInterval(500)` → `analyzeTodayDiag()` |

`analyzeTodayDiag` clonait tout le buffer (`events.map(e => ({...e}))`) puis `analyzeInteractions` en O(interactions × events). Avec un buffer qui grossit, ~460 ms toutes les ~500 ms = saturation quasi continue — **indépendante de SidebarPremium**.

### Pourquoi la Phase C ?

Après ~128 s : plus aucune LT, interactions ~24 ms. Hypothèse principale : **panneau fermé** (ou plus d’analyse 2×/s) après la rafale métier Phase B. Aucun marqueur utilisateur ne le prouve ; la cadence 467 ms ↔ 500 ms suffit à incriminer le panneau pour la Phase A.

### Correctifs livrés

| Changement | Effet |
|---|---|
| Compteurs lite O(1) (`snapshotTodayDiagLite`) | Vue d’ensemble sans parcours buffer |
| Plus de rebuild 2×/s | Analyse complète = ouverture / vue détaillée / « Actualiser » / export |
| `snapshotTodayDiag({ cloneEvents: false })` pour l’analyse | Plus de clone systématique |
| `analyzeInteractions` indexé une fois | Fini le O(n×m) naïf |
| `instrumentationOverhead.panelAnalyzeMs` | Surcoût présentation mesuré (pas seulement pushMs) |

**Conduite de test :** campagne avec panneau **fermé** vs **ouvert** (vue overview uniquement) vs bouton Actualiser — la bande 470 ms doit disparaître dès que l’analyse n’est plus périodique.
